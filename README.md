# Market Voice Bot

Telegram-бот, который следит за крипто-новостями в RSS-лентах, переписывает
каждую новость в авторский пост с помощью LLM (Groq) и публикует результат
в Telegram-канал. Запускается по расписанию в GitHub Actions — отдельный
сервер не нужен.

## Как это работает

```
RSS-ленты  →  фильтр "новое ли это"  →  Groq (LLM)  →  Telegram
   │                    │                                  │
   │                    └── SQLite (data/state.db) ─────────┘
   │                        хранит обработанные ссылки
   ▼
несколько источников читаются параллельно,
ошибка в одной ленте не мешает остальным
```

1. **`rss_fetcher`** читает все RSS-ленты из конфига и превращает записи в
   единый список новостей. Падение одной ленты (недоступна, битый XML) не
   прерывает обработку остальных.
2. **`storage`** (SQLite) хранит ссылки на уже обработанные новости —
   опубликованные или пропущенные ИИ. Каждая ссылка проверяется независимо,
   поэтому изменение порядка записей в ленте не приводит к дублям или
   пропускам, как это было бы при хранении только "последней" ссылки.
3. **`ai_writer`** отправляет сырой текст новости в Groq с промптом,
   задающим стиль и формат поста. Если новость не несёт ценности, модель
   отвечает `SKIP`, и пост не публикуется. При сетевой ошибке — до 3 попыток
   с экспоненциальной паузой.
4. **`telegram_client`** публикует готовый пост в канал. Обрабатывает
   `429 Too Many Requests` (ждёт `retry_after` из ответа API) и обрезает
   текст, если он длиннее лимита Telegram в 4096 символов.
5. **`main`** связывает всё вместе: получает новости → отбирает необработанные
   → ограничивает количество за один запуск → генерирует и публикует.

## Структура проекта

```
market-voice-bot/
├── market_voice_bot/
│   ├── config.py           # загрузка и валидация настроек из env
│   ├── storage.py          # SQLite-хранилище обработанных ссылок
│   ├── rss_fetcher.py       # чтение и парсинг RSS
│   ├── ai_writer.py         # генерация постов через Groq
│   ├── telegram_client.py   # отправка сообщений в Telegram
│   └── main.py               # точка входа, оркестрация
├── tests/                    # юнит-тесты (pytest, всё замокано — сеть не нужна)
├── data/                      # data/state.db — файл состояния (коммитится ботом)
├── .github/workflows/
│   ├── bot.yml                # расписание — сам бот
│   └── ci.yml                  # тесты + линт на каждый push/PR
├── .env.example
├── requirements.txt
├── requirements-dev.txt
└── pyproject.toml
```

## Настройка

### 1. Переменные окружения

Обязательные:

| Переменная      | Описание                                              |
|-----------------|--------------------------------------------------------|
| `GROQ_API_KEY`  | API-ключ Groq (console.groq.com)                       |
| `BOT_TOKEN`     | Токен Telegram-бота от [@BotFather](https://t.me/BotFather) |
| `CHANNEL_ID`    | ID канала/чата, куда публиковать (например `@my_channel`) |

Необязательные (значения по умолчанию — в `market_voice_bot/config.py`):

| Переменная         | По умолчанию              | Описание                                  |
|--------------------|----------------------------|--------------------------------------------|
| `GROQ_MODEL`        | `llama-3.1-8b-instant`     | Модель Groq для генерации постов           |
| `RSS_URLS`           | 3 крипто-ленты (см. `config.py`) | Список ссылок через запятую          |
| `MAX_NEWS_PER_RUN`   | `5`                         | Сколько новостей обрабатывать за один запуск |
| `DB_PATH`             | `data/state.db`            | Путь к файлу состояния                     |
| `LOG_LEVEL`            | `INFO`                      | Уровень логирования                        |

Локально скопируйте `.env.example` в `.env` и заполните значения (для
локального запуска понадобится что-то вроде `python-dotenv`, либо просто
экспортируйте переменные в shell).

### 2. GitHub Actions (продакшн)

В настройках репозитория **Settings → Secrets and variables → Actions**
добавьте три секрета: `GROQ_API_KEY`, `BOT_TOKEN`, `CHANNEL_ID`.

Workflow `.github/workflows/bot.yml` запускается по расписанию (по умолчанию
каждые 15 минут), выполняет один проход бота и коммитит обновлённый
`data/state.db` обратно в репозиторий — так состояние переживает следующий
запуск раннера. Также его можно запустить вручную через
**Actions → Run Market Voice Bot → Run workflow**.

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export GROQ_API_KEY=...
export BOT_TOKEN=...
export CHANNEL_ID=...

python -m market_voice_bot.main
```

## Тесты и линтинг

```bash
pip install -r requirements-dev.txt

pytest --cov=market_voice_bot     # юнит-тесты с покрытием
ruff check .                       # линтер
black --check .                    # проверка форматирования
```

Все тесты изолированы моками (Groq, `requests`, `feedparser`) — сеть и
настоящие ключи API для запуска тестов не нужны.

## Возможные дальнейшие улучшения

- Вынести список RSS-источников в отдельный YAML/JSON, если он будет расти.
- Добавить уведомление в отдельный Telegram-чат при падении workflow.
- Поддержка нескольких каналов с разным стилем постов под каждый.
- Дедупликация похожих новостей из разных источников (например, по similarity заголовков).
